1. ЧТО ЭТО
────────────────────────────────────────────────────────────────

NeuroObfuscator — система защиты JavaScript-кода, в которой
нейросеть принимает стратегические решения о том, КАК запутать
код, а детерминированный движок эти решения исполняет.

Модель не пишет код. Модель пишет ПЛАН обфускации:

    • какие трансформации применить;
    • в каком порядке;
    • с какой интенсивностью.

Движок на Babel берёт этот план и физически меняет AST кода.


2. ЗАЧЕМ ЭТО СУЩЕСТВУЕТ
────────────────────────────────────────────────────────────────

Существующие обфускаторы (javascript-obfuscator, UglifyJS)
применяют фиксированный набор правил ко всему коду одинаково.
Они не понимают структуру кода:

    ✗ обфусцируют горячие циклы так же агрессивно,
      как мёртвые утилиты;
    ✗ применяют тяжёлые трансформации там,
      где достаточно переименования;
    ✗ не адаптируются к сложности кода.

NeuroObfuscator решает это: модель анализирует AST-признаки
(число ветвлений, циклов, строк, сложность) и подбирает
оптимальную стратегию для каждого конкретного куска кода.


3. ЧТО ЭТО НЕ
────────────────────────────────────────────────────────────────

Это не замена Denuvo.

    Denuvo            — криптографическая виртуальная машина
                        для бинарного кода.
    NeuroObfuscator   — интеллектуальный оркестратор обфускации
                        для исходного кода.

Разные уровни, разные задачи.


4. КАКУЮ ПРОБЛЕМУ РЕШАЕТ В ПОРТФОЛИО
────────────────────────────────────────────────────────────────

Проект демонстрирует три навыка:

    1. ML-инженерия
       дообучение LLM через QLoRA, генерация структурированного
       вывода, валидация;

    2. Решение нестандартных задач
       код не шифруется, а трансформируется с сохранением
       семантики;

    3. Умное использование ресурсов
       адаптация модели и стратегии к доступному железу.

7. ТРАНСФОРМАЦИИ (10 ШТУК)
────────────────────────────────────────────────────────────────

 #   Название               Что делает
─────────────────────────────────────────────────────────────────
 1   rename                 Переименование идентификаторов в _0x3f2a

 2   string_encode          Кодирование строк в charcode/hex/base64

 3   dead_code              Вставка недостижимых веток

 4   operator_sub           Замена a+b на a-(-b) и т.д.

 5   opaque_predicates      Условия, всегда true/false, но выглядящие сложно

 6   loop_transform         Замена типа цикла, разворачивание в рекурсию

 7   control_flow_flatten   if/else → switch-based state machine

 8   inline_functions       Встраивание тела функции вместо вызова

 9   array_wrapper          Доступ к свойствам через массив индексов

10   self_defending         Проверки целостности кода


8. ЧТО НЕ ИСПОЛЬЗОВАТЬ
────────────────────────────────────────────────────────────────

НЕ использовать                          Почему
─────────────────────────────────────    ────────────────────────────────────────────────────
Регулярные выражения для                 Не понимают структуру. Заменят var x внутри
трансформации кода                       строки или комментария

Генерацию кода моделью напрямую          Модель сломает синтаксис. Генерировать план,
                                         исполнять движком

TypeScript / JSX в v1                    Усложняет AST-анализ, сужает датасет.
                                         Добавить в v2

Бинарную обфускацию / ассемблер          Требует месяцев изучения, не нужен
                                         для портфолио ML-инженера

Криптографию как замену обфускации       Это задача Denuvo, не ваша. Вы делаете
                                         интеллектуальную обфускацию

GPT-4 API для генерации датасета         Дорого, медленно, нестабильно. Генерировать
                                         синтетически через Babel

React / Angular / Vue для демо           Избыточно. Gradio закрывает все потребности
                                         за 1 день

Docker / Kubernetes                      Избыточно для портфолио-проекта.
                                         Makefile достаточно

Обучение модели на локальном             6GB VRAM мало для обучения 7B.
GTX 1660 Super                           Обучать на Colab, инференс локально

CSV / Excel для датасета                 Не поддерживает вложенные JSON-планы

Ручную разметку датасета                 Генерировать автоматически через Babel + тесты


9. АНТИПАТТЕРНЫ
────────────────────────────────────────────────────────────────

Антипаттерн                              Почему плохо                  Что делать вместо
─────────────────────────────────────    ──────────────────────────    ────────────────────────────────────────
Модель выдаёт текст с пояснениями        Парсер ломается               Промпт: «Output ONLY valid JSON»
вокруг JSON                                                            + валидация

Все трансформации применяются всегда     Код раздувается,              Модель решает, какие нужны
                                         производительность падает

Нет unit-тестов обфусцированного кода    Обфускация ломает логику,     Автотесты на каждый кандидат
                                         никто не замечает

Порядок трансформаций случайный          rename после flatten ломает   Топологическая сортировка по
                                         переменные state machine      зависимостям

Один фиксированный системный промпт      Модель не видит структуру,    AST-признаки как JSON в промпте
без AST-признаков                        предлагает нерелевантные
                                         трансформации

Обучение без валидационного сета         Переобучение, нет метрик      80/10/10 split со стратификацией
                                         качества


10. КАК ЭТО ИСПОЛЬЗОВАТЬ
────────────────────────────────────────────────────────────────

СЦЕНАРИЙ 1 · Генерация датасета (локальный ПК, 1–2 дня)
....................................................................

  Шаг 1. Собрать JS-код
          → python scripts/01_collect.py
          → Результат: data/raw/ (100K+ файлов)

  Шаг 2. Отфильтровать и извлечь функции
          → python scripts/02_filter.py
          → Результат: data/filtered/functions.jsonl (40K функций)

  Шаг 3. Извлечь AST-признаки
          → python scripts/03_extract_features.py
          → Результат: features.jsonl с branch_count, loop_count,
            entropy...

  Шаг 4. Сгенерировать случайные планы
          → python scripts/04_generate_plans.py
          → Результат: 200–400K кандидатов (код + план)

  Шаг 5. Применить трансформации + тесты
          → python scripts/05_apply_and_validate.py
          → Результат: обфусцированный код + tests_passed

  Шаг 6. Отобрать лучшие
          → python scripts/06_score_and_select.py
          → Результат: 5–10K лучших пар

  Шаг 7. Форматировать для CodeLlama
          → python scripts/07_format_for_training.py
          → Результат: formatted.jsonl (system + input + output)

  Шаг 8. Разделить на train/val/test
          → python scripts/08_split_dataset.py
          → Результат: train.jsonl, val.jsonl, test.jsonl

  Шаг 9. Загрузить на Google Drive
          → Перетащить папку data/final/ в Drive

СЦЕНАРИЙ 3 · Инференс и демо (локально или Colab)
....................................................................

  Шаг 1. Пользователь вставляет JS-код в Gradio-интерфейс
  Шаг 2. Система парсит код → AST → извлекает признаки
  Шаг 3. Модель генерирует JSON-план
  Шаг 4. Валидатор проверяет план (JSON Schema + логика)

          • JSON-план модели;
          • метрики до/после;
